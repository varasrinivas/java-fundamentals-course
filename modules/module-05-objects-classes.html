A class is a blueprint; new stamps out objects

In Java, almost everything you build is a class with fields, a constructor, and methods. There are no free functions and no top-level code — understanding the new→allocate→construct sequence is understanding how Java programs come alive.

Concept

From class definition to living object

🏷 Real-world analogy

A class is an architect's blueprint — it describes what every house of this kind will have (rooms, wiring, a front door) but is not itself a house you can live in. An object is an actual house built from that blueprint: it occupies real ground (heap memory), and you can build a hundred of them, each with its own address and its own paint colour. The constructor is the assembly line that stamps out each house and does the finishing work — laying the foundation, then setting the specific details you asked for — so that the moment the keys are handed over (new returns), the house is already in a valid, move-in-ready state and no one ever sees a half-built shell.

A class declares state (fields) and behavior (methods). A constructor runs once, right after allocation, to put a new object into a valid initial state. The new operator does three things in order: allocate heap memory, run the constructor, hand back a reference.

Fields default to zero / false / null before the constructor runs. The constructor's job is to replace those defaults with meaningful values — ideally leaving no half-built object observable.

    


    
Anatomy of a class: fields, methods, constructors

    
Three kinds of members make up a typical class. Fields hold per-instance state; methods are the behaviour that reads or mutates that state; and constructors initialize a fresh instance. A constructor looks like a method but has no return type and shares the class's exact name — that's how the compiler tells them apart. Everything an object can do is a member; Java has no free-standing functions living outside a class.

    


    
The default constructor and constructor overloading

    
If you write no constructor at all, the compiler synthesizes an invisible no-arg default constructor that just calls super(). The instant you declare any constructor of your own, that freebie disappears — a common surprise when new Foo() suddenly stops compiling. You can offer several ways to build an object by overloading: multiple constructors that differ in their parameter lists.

    


    
Constructor chaining with this(...) and super(...)

    
A constructor may hand off work to another. this(...) calls a sibling constructor in the same class (removing duplicated setup); super(...) calls a constructor of the parent class. Whichever you use, the call must be the very first statement in the constructor body — you cannot do both, and you cannot put code before it. If you write neither, the compiler silently inserts super(), so a parent chain always runs top-down before the current constructor's own body.

    


    
Object initialization order

    
Initialization runs in a fixed, testable sequence. The first time a class is used, its static fields and static { } blocks run once, top to bottom. Then, on every new: the superclass is fully initialized first (via the super() chain), then this class's instance field initializers and instance { } blocks run in source order, and finally the constructor body executes. Knowing this order explains why a field can look "already set" before the constructor's assignment.

    


    
new, the heap, and the reference variable

    
new allocates the object on the heap and returns a reference — a handle, not the object itself. The variable on the stack holds that reference. Two variables can point at the same object, so a mutation through one is visible through the other; == compares references (same object?), while .equals() compares contents. A variable that references nothing holds null.

    


    
this and field shadowing

    
this is the implicit reference to the current object. You mostly need it to disambiguate when a parameter or local variable shadows a field with the same name — a near-universal idiom in constructors and setters. Without this., the nearer-scoped name wins and you end up assigning the parameter to itself.

    


    
Static factory methods as an alternative to new

    
Not every object has to be born from new at the call site. A static factory method is a static method that returns an instance, and the JDK leans on them heavily: List.of(...), Optional.of(x), Integer.valueOf(7). Unlike a constructor, a factory has a meaningful name, may return a cached instance instead of a brand-new one, and can hand back a subtype — freedom a constructor can never offer.

Coming from another language

    
What will surprise you

      
Coming from Python
No self as an explicit first parameter — Java uses an implicit this. And Java's constructor is named after the class, not __init__. Fields are usually declared up front, not created ad-hoc in the constructor.

      
Coming from JavaScript
Java classes aren't sugar over prototypes — they're the real, only model. There's no object literal {}; you must define a class (or a record) first. Visibility (private) is enforced by the compiler, not a # convention.

      
Coming from C#
Very close: fields, constructors, this, and new all match. Java lacks C# properties (get; set;), so you'll write explicit getter/setter methods or use records.

  






  

    
Exercises

    
Make it stick

      
1 · Default before construct
A class has an int count; field and a constructor that doesn't touch it. What is count right after new?
💡 Show hint
0. Numeric fields default to 0, booleans to false, and object references to null — before and unless the constructor overrides them.

      
2 · Why private?
Why make balance private and expose deposit() instead of letting callers set it directly?
💡 Show hint
Encapsulation: the class controls its invariants. deposit() can validate (reject negatives), log, or notify. A public field gives callers raw access with no guardrails.

      
3 · The vanishing default constructor
You add one constructor Box(int size) to a class that previously had none. Suddenly new Box() stops compiling. Why, and how do you fix it while keeping the new one?
💡 Show hint
The compiler only supplies the no-arg default constructor when you declare no constructors at all. Once you write Box(int), that freebie is gone. Fix it by explicitly declaring the no-arg one too: Box() { this(0); } — overloading gives you both.

      
4 · Two names, one object
After Account a = new Account(100); Account b = a; b.deposit(50);, what does a.balance() return? And what is a == b?
💡 Show hint
150, and a == b is true. b = a copies the reference, not the object — both variables point at the same heap instance, so a mutation through b is visible through a.

      
5 · What runs first?
A class has an instance field initializer int id = ++made;, an instance { } block, and a constructor body that also prints id. In what order do these three run on a single new?
💡 Show hint
After the implicit super(), the field initializers and instance blocks run first, in source order, and the constructor body runs last. So id is already assigned by the time the constructor body executes — the constructor sees the fully-initialized field.
