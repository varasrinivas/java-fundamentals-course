A type with a fixed set of values

An enum is a class whose instances are a known, finite list — Monday through Sunday, not “any string that might be a day.” Java enums go far beyond C-style integer constants: they carry fields, methods, and even per-constant behavior.

Concept

Type-safe constants that are real objects

🃏 Real-world analogy

An enum is a sealed deck of trading cards. The whole set is printed at the factory (compile time) — there are exactly four suits, or the four compass directions NORTH, EAST, SOUTH, WEST, and you cannot invent a fifth card at the table mid-game (no new instances at runtime). Yet each card is more than a name: it carries its own stats printed on the face (fields like a planet’s mass and radius), and a rare card can even have its own special move that behaves differently from every other card (a constant-specific method). Because the deck is finite and known, the dealer (the compiler) can guarantee a rule covers every card — that is the exhaustive switch.

Each enum constant is a singleton instance of the enum type. Because the set is closed, the compiler can make a switch exhaustive, and you get name(), ordinal(), and values() for free. Enums can also declare fields and methods.

Prefer enums over int or String constants: they're type-safe (you can't pass "mosday"), self-documenting, and work in switch and EnumMap. They're also the simplest correct way to write a singleton.

    

    
Why enums beat int / String constants

    
The pre-Java-5 “int enum pattern” — a pile of static final int values — is a well-known anti-pattern. Nothing stops you passing 99 where a suit is expected, a debugger prints 0 instead of HEARTS, and adding a constant can silently shift every literal. An enum gives you a distinct type, a real namespace, and a printable name — all checked by the compiler.

    

    
Fields, a constructor, and methods

    
An enum is a full class, so each constant can bundle data. You attach values in the constant list; those arguments are passed to a private constructor (enum constructors are implicitly private — you can never call new yourself). Give the fields final and the enum stays immutable, which is exactly what you want for a fixed set.

    

    
Enums in switch & exhaustiveness

    
Inside a switch you write the bare constant name — case MONDAY, not case Day.MONDAY — because the switched type is already known. A modern switch expression (Java 14+) over an enum must cover every constant or the code won’t compile, so adding a new constant turns a forgotten branch into a compile error rather than a silent bug. If you add a default, though, you give up that safety net.

    

    
Constant-specific behavior (abstract method per constant)

    
Instead of a giant switch that everyone forgets to update, declare an abstract method on the enum and let each constant supply its own implementation in a little class body. This is the “constant-specific method” idiom from Effective Java: adding a new constant forces you to define its behavior, and the logic lives right next to the constant it belongs to.

    

    
EnumSet & EnumMap

    
When your keys or elements are enum constants, skip HashSet/HashMap. EnumSet is internally a bit vector (one bit per constant), so membership tests and set algebra are blazing fast and compact; EnumMap is backed by a plain array indexed by ordinal. Both are purpose-built, ordered by declaration, and reject non-enum keys at compile time.

    

    
Implementing interfaces & the enum singleton

    
An enum can’t extend a class (it already extends java.lang.Enum), but it can implement interfaces — handy for a fixed family of strategies. And because the JVM guarantees exactly one instance of each constant, a single-constant enum is the most robust singleton in Java: it’s serialization-safe and reflection-proof for free, per Effective Java. Round-trip a constant with name() and valueOf; treat ordinal() as a private implementation detail (never persist it).

Coming from another language

    
What will surprise you

      
Coming from Python
Java enums are like enum.Enum but richer: each constant is a singleton object that can have constructors, fields, and methods, and even override a method per-constant. The exhaustive-switch guarantee has no plain-Python equivalent.

      
Coming from JavaScript
JS has no native enum — people fake it with frozen objects or string unions (TypeScript). Java's enum is a real, type-checked type, so a typo like Day.MODNAY won't compile.

      
Coming from C#
C# enums are thin wrappers over integers; any in-range int casts to one. Java enums are full objects with no implicit int conversion — safer, and they can hold behavior C# enums can't.

  






  

    
Exercises

    
Make it stick

      
1 · Why not int constants?
Name two concrete advantages of enum Suit { HEARTS, ... } over static final int HEARTS = 0;.
💡 Show hint
Type safety (a method taking Suit can't receive a stray int like 99) and exhaustiveness/readability (switch coverage is checked; toString prints HEARTS, not 0). Bonus: they work as EnumMap/EnumSet keys.

      
2 · ordinal() trap
Why is persisting ordinal() to a database a bug waiting to happen?
💡 Show hint
Ordinal is just declaration position. Reorder or insert a constant and every stored number now maps to a different value. Persist name() (or an explicit code field) instead.

      
3 · One method, many behaviors
You have enum Operation { PLUS, MINUS, TIMES, DIVIDE } and want op.apply(a, b) to compute the right result. Sketch the enum without a switch.
💡 Show hint
Declare public abstract int apply(int a, int b); on the enum, then give each constant its own body: PLUS { public int apply(int a,int b){ return a+b; } }, and so on. Adding a new operation then forces you to implement apply — a missing case becomes a compile error, not a runtime surprise.

      
4 · Which map for a schedule?
You’re mapping each Day to a task string. Why prefer EnumMap<Day,String> over HashMap<Day,String>?
💡 Show hint
EnumMap is backed by a plain array indexed by the constant’s ordinal — no hashing, no buckets, less memory, and iteration comes out in declaration order. It also rejects non-Day keys at compile time. It’s the purpose-built map when every key is an enum constant.

      
5 · The bulletproof singleton
Effective Java calls the single-element enum “the best way to implement a singleton.” What two attacks does it defend against that a hand-written private static final INSTANCE does not?
💡 Show hint
Reflection (someone calling the private constructor via setAccessible(true)) and serialization (deserializing creates a second instance). The JVM makes enum constants immune to both automatically, so enum Foo { INSTANCE; } stays a true singleton with no extra readResolve or guard code.
