Share the common bits to save memory

Real-world picture: a forest in a video game with a million trees. Each tree has its own position, but they don’t each need their own copy of the 3D mesh and texture — they can all point at one shared “oak” model. Flyweight shares the common, repeated state across many objects to slash memory use.

Concept

Split state into shared and unique

The key move is separating intrinsic state (shared, the same for many objects — the mesh, the texture) from extrinsic state (unique per object — the x/y position). The intrinsic part becomes an immutable flyweight stored once; a factory hands out the same instance for the same key.

You’ve already met a flyweight: Java caches small Integer objects (−128..127, module 04) and interns String literals (module 15) — both are flyweights. It’s a memory optimization, so reach for it only when you truly have a huge number of similar objects.

Coming from another language

    
What will surprise you

      
Coming from Python
sys.intern() shares identical strings, and small ints are cached — built-in flyweights, just like Java’s Integer cache and String pool. Same memory-sharing idea at the language level.

      
Coming from JavaScript
Engines intern strings and share immutable values; you apply the pattern by reusing one shared object reference across many items instead of cloning it.

      
Coming from C#
String interning and the choice of struct vs class drive the same memory concerns. A cache returning shared immutable instances is the explicit flyweight.

  






  

    
Exercises

    
Make it stick

      
1 · Intrinsic vs extrinsic
For a million on-screen characters of text, which state is intrinsic (shared) and which is extrinsic (unique)?
💡 Show hint
Intrinsic (shared): the glyph shape/font data for each character code — one ‘A’ glyph reused everywhere. Extrinsic (unique): each character’s position, size, color on the page. The flyweight stores the glyph once.

      
2 · Must it be immutable?
Why must the shared flyweight state be immutable?
💡 Show hint
Because it’s shared by many objects — if one could mutate it, every object using that flyweight would change too. Immutability makes the sharing safe (and thread-safe).
